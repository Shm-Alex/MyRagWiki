# 🧠 MyRagWiki — Персональная RAG-система на .NET

> ️ **Это мой первый экспериментальный проект в области RAG/Ollama/LLM.** 
> Проект создан в рамках инициативы **Career CoPilot** — идеи персонального ИИ-ассистента для управления карьерой. Код написан в учебных целях, чтобы понять архитектуру RAG «под капотом» перед переходом к более серьёзной реализации (ASP.NET Core Web API + DDD + PostgreSQL + pgvector).

Персональная база знаний с ИИ-поиском, работающая полностью **локально** (без отправки данных в облако). Проект реализует архитектуру **RAG (Retrieval-Augmented Generation)** на чистом C# с использованием локальных моделей через Ollama.

---

## 🎯 Что делает проект

Система позволяет задавать вопросы о вашем профессиональном опыте (резюме, проекты, навыки) и получать **точные ответы без галлюцинаций**, основанные исключительно на фактах из вашей базы знаний.

### Ключевые возможности:
- 🔍 **Семантический поиск** — находит релевантные фрагменты по смыслу, а не по ключевым словам
-  **Локальный ИИ** — все данные остаются на вашем компьютере
- 📴 **Работает без интернета** — после загрузки моделей
-  **Без галлюцинаций** — ИИ отвечает только на основе предоставленного контекста

## 🏗 Архитектура

Проект реализует классический RAG-пайплайн в 4 этапа:

```
─────────────────────────────────────────────────────────────┐
│  1. ИНГЕСТЦИЯ                                                │
│  Резюме разбивается на смысловые чанки                      │
│  (по местам работы: TERN, Amdocs, ПСБ, IBS, Mont...)        │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────
│  2. ВЕКТОРИЗАЦИЯ (Embedding)                                │
│  Каждый чанк → вектор из 768 чисел через nomic-embed-text   │
│  (отражает смысл текста, а не просто слова)                 │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  3. ПОИСК (Retrieval)                                       │
│  Запрос пользователя тоже превращается в вектор             │
│  Вычисляется косинусное сходство с каждым чанком            │
│  Выбирается наиболее релевантный фрагмент                   │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  4. ГЕНЕРАЦИЯ (Generation)                                  │
│  Релевантный чанк + вопрос → промпт → qwen2.5-coder:14b     │
│  Получаем структурированный ответ на русском                │
└─────────────────────────────────────────────────────────────┘
```

## 📋 Требования

### Обязательные:
- [.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0)
- [Ollama](https://ollama.com/) (установлен и запущен)
- Модели Ollama:
  - `nomic-embed-text` — для векторизации (274 МБ)
  - `qwen2.5-coder:14b` — для генерации ответов (9 ГБ)

### Установка моделей:
```bash
ollama pull nomic-embed-text
ollama pull qwen2.5-coder:14b
```

### Проверка:
```bash
ollama list
```
Должны увидеть обе модели в списке.

## 💻 Как это работает (пошагово)

### Шаг 1: Проверка подключения
```csharp
var isAlive = await ollama.IsAliveAsync();
// GET http://localhost:11434/api/tags
```

### Шаг 2: Векторизация базы знаний
```csharp
chunk.Embedding = await ollama.GetEmbeddingAsync(chunk.Text, "nomic-embed-text");
// POST http://localhost:11434/api/embed
// Возвращает float[768] — вектор смысла текста
```

### Шаг 3: Косинусное сходство
```csharp
float CosineSimilarity(float[] a, float[] b)
// Чем ближе к 1.0 — тем больше смысловое совпадение
```

### Шаг 4: Генерация ответа
```csharp
var prompt = $"Используй ТОЛЬКО этот факт: {bestMatch.Chunk.Text}\nВопрос: {query}";
var response = await ollama.GenerateAsync(prompt, "qwen2.5-coder:14b");
```

##  Чему я научился в этом эксперименте

1. **Ollama API прост и понятен** — всего 3 эндпоинта (`/api/tags`, `/api/embed`, `/api/generate`) покрывают 90% задач RAG
2. **Векторизация — это магия, но понятная** — текст превращается в 768 чисел, и косинусное сходство реально работает
3. **Маленькие модели галлюцинируют** — `Qwen3-VL-4B` в AnythingLLM выдумывал Azure, которого нет в моём резюме. `qwen2.5-coder:14b` с жёстким промптом ведёт себя честно
4. **RAG — это не сложно** — ядро системы уместилось в ~150 строк C# без внешних библиотек
5. **Семантический поиск > ключевые слова** — запрос "миграция БД" находит Amdocs, даже если там нет слова "миграция" в точной форме

## ⚠️ Известные ограничения

- **Размер контекста**: модель `qwen2.5-coder:14b` имеет ограничение на длину промпта (~32k токенов)
- **Скорость**: первая генерация может занять 10-30 секунд (загрузка модели в память)
- **Качество поиска**: простое косинусное сходство работает хорошо, но для больших баз лучше использовать HNSW-индексы (например, через Qdrant или pgvector)
- **Хардкод данных**: чанки сейчас зашиты в код — в следующей итерации будет парсинг файлов
